## 요구사항 요약

- 공정 설명 + I/O 할당표 → 미쓰비시 Q(Q03UDV) + GX Works2용 래더 CSV 생성 (PRD 1, 4)
- Electron + React + TypeScript 데스크톱 앱, 한국어 UI, 단일 사용자 (PRD 2, 5-2)
- LLM은 공정 해석에만 사용: 기본 `claude -p`, 대안 Claude API `claude-opus-5-5` (PRD 4, 5-3)
- 단계 표 이후(생성·검증·배치·내보내기)는 결정적 순수 함수 (PRD 5-2 설계 원칙)
- 공정 범위: 순차, 반복, 횟수, 선택 분기, 병렬 분기·합류 (PRD 4)
- 운전 모드: 자동, 사이클 정지, 비상정지, 수동, 원점복귀, 이상 감지·리셋(이상 번호 D 기록) (PRD 5-1, 5-4)

## 구조

```
src/core/        순수 TypeScript, Electron·React 의존 없음
  types.ts       태그, 단계 표, 운전 설정, 명령(Instruction), 렁(Rung)
  tags.ts        할당표 행 → 태그 목록 + 오류 (주소 형식, 중복, 필수 열)
  steptable.ts   단계 표 스키마(zod) + 구조 검사 (도달 불가, 합류 없는 병렬)
  generate.ts    단계 표 + 운전 설정 → 렁 목록 (PRD 5-4 블록 1~8)
  verify.ts      렁 목록 → 오류·경고 (PRD 4 자동 검증)
  export.ts      렁 목록 → 프로그램 CSV / 코멘트 CSV (PRD 5-3 형식)
  layout.ts      렁 → 접점·코일 격자 좌표
  prompt.ts      공정 해석 프롬프트 + 응답 파싱
src/main/        Electron 메인: 파일 입출력, LLM 실행(claude -p / API), 설정·키 보관
src/renderer/    React 화면: 할당표 → 공정 입력 → 운전 설정 → 단계 표 → 결과
tests/           vitest. fixtures/(샘플 CSV, 기준 공정 4종), sim.ts(테스트 전용 스캔 해석기)
```

- 렁마다 `source`(단계·전이·블록 종류)를 붙여 생성 → 렁별 설명과 오류 위치 표시에 그대로 사용
- `tests/sim.ts`: 명령어 리스트를 스캔 단위로 실행하는 테스트 전용 해석기. GX Works2 없이 기준 공정 동작을 자동 확인하는 유일한 수단. 앱 기능(P1 시뮬레이션)으로는 넣지 않음

## 구현 단계

### M0. 뼈대
- electron-vite(React + TypeScript 템플릿)로 스캐폴드, vitest 추가, `git init`
- 구현 전 electron-vite 공식 문서로 현재 스캐폴드 명령 확인
- 완료 조건: `npm run dev`로 빈 창 표시, `npm test` 통과(빈 테스트 1개)

### M1. 내보내기 (위험이 가장 큰 부분 먼저)
- `types.ts`의 Instruction, `export.ts`
- 스텝 수 표: 1스텝(LD, LDI, AND, ANI, OR, ORI, ORB, ANB, OUT M·Y, SET, RST, END), 2스텝(MOV, PLS), 3스텝(비교 접점), 4스텝(OUT T/C + K)
- 완료 조건
  - 샘플과 같은 명령 목록을 넣으면 출력이 `MAIN.csv`와 **바이트 단위로 일치** (UTF-16 LE BOM, 탭, CRLF)
  - 코멘트 2건을 넣으면 `COMMENT.csv`와 바이트 단위로 일치 (LF)
  - 코멘트 칸 수 계산: 한글 2칸·영문 1칸, 윗줄 8칸 채움, 16칸 초과 시 잘라내고 경고

### M2. 순차 공정 생성 + 첫 불러오기 관문
- `steptable.ts`, `generate.ts`(블록 2, 3, 4, 8만: 전이 비트, 단계 SET/RST, 타이머, 출력), `verify.ts`(할당표 밖 주소, 이중 코일, 미사용 출력), `tests/sim.ts`
- 기준 공정 "실린더 순차 왕복", "신호등"을 단계 표 fixture로 작성
- 완료 조건
  - sim에서 A+ B+ B- A- 순서로 출력 변화, 신호등 3사이클 반복
  - 전이 조건이 연속으로 참이어도 한 스캔에 한 단계만 진행
  - 같은 입력 2회 생성 결과 동일
- **사용자 확인 관문**: 생성된 CSV 2종을 GX Works2에 불러와 (1) 변환 오류 0건 (2) 스텝 번호 문제 없음 (3) 코멘트 2행 표시 확인. 실패하면 M1 형식부터 수정하고 다음 단계로 가지 않음

### M3. 생성 규칙 전체
- 선택 분기(우선순위 B접점), 병렬 분기·합류, 카운터
- 운전 모드 블록 1, 5, 6, 7: 자동 운전 조건, 사이클 정지, 비상정지, 수동, 원점복귀, 이상 감지(제한 시간, 센서 쌍) + 이상 번호 MOV, 리셋
- B접점 입력 반전, 인터록 쌍
- `verify.ts` 나머지: 인터록 누락, 도달 불가 단계, 합류 없는 병렬
- 기준 공정 "컨베이어 분류", "두 실린더 동시 동작" fixture 추가
- 완료 조건: PRD 5-6 "래더 생성", "자동 검증", "이상 상황" 항목을 sim 테스트로 전부 통과 (LLM·GX Works2 항목 제외)

### M3-T. PlcTwin 연동 (M3 직후)
- 선행 조건: D 비트 접점·코일과 `LD SM400`이 든 GX Works2 샘플 CSV 수령 → `stepCount`에 반영, 바이트 일치 테스트 추가
- 주소: `D0.F` 형식(워드 비트)과 `D144` 형식(워드) 허용, D 주소는 방향 필수
- 단계의 고정값 쓰기(`writes`), 운전 설정의 `alwaysOn` / `alwaysWrites`
- 검증 추가: 입력 주소에 쓰는 명령, 내부 디바이스(M, T, C, D)와 할당표 주소의 겹침
- 기준 공정 "MPS 라인" fixture: PlcTwin README의 디바이스 맵으로 작성 (공급 → 송출 → 컨베이어 → 스토퍼·판별 → 가공 → 배출 → 서보 적재), 단계 정의는 사용자 확인
- `plc_twin` 폴더는 읽기만 하고 수정하지 않음. PlcTwin 실행·Connect는 사용자가 함 (시뮬레이터에만 연결)
- 완료 조건: sim 테스트에서 MPS 라인 단계가 끝까지 진행 + **사용자 확인**: GX Simulator2 RUN + PlcTwin MX 연결에서 칩 1개가 공급부터 적재까지 이동

### M4. 할당표 입력
- PlcTwin의 `device_comments.xlsx`를 읽어 태그 목록으로 만드는 테스트 포함
- `tags.ts`, 메인 프로세스의 xlsx/csv 읽기 (xlsx 라이브러리는 구현 시 선정, 현재 권장 버전 확인)
- 붙여넣기(탭 구분 텍스트) 파싱, 열 지정
- 완료 조건: PRD 5-6 "I/O 할당표 입력" 5개 항목 통과

### D. 디자인 확정 (M2 관문 통과 후, M5 시작 전)
- 정할 것: 화면 구성(단계형 마법사 / 한 창 패널), 시각 방향(색, 글꼴, 밝은·어두운 테마), 래더 그림 스타일(GX Works2와 유사 / 재디자인)
- 방법: 선택지를 하나씩 질문 → 5개 화면 시안 작성 → 사용자 확인
- 완료 조건: 사용자가 승인한 시안과 디자인 값(색, 글꼴, 간격)이 문서로 남음. 승인 전 M5 진행 안 함

### M5. 화면 흐름 + 프로젝트 저장
- D에서 승인된 디자인대로 구현
- 5개 화면(할당표 표, 공정 입력, 운전 설정, 단계 표, 결과)과 상태 전이 (PRD 5-4 앱 작업 상태)
- 운전 설정 추정(이름 키워드) → 확인 전 미적용
- 단계 표 편집기: 단계·전이·카운터 행 추가·수정·삭제
- 프로젝트 JSON 저장·열기, CSV 내보내기 대화상자
- 완료 조건: LLM 없이 기준 공정 4종을 화면에서 입력 → CSV 내보내기까지 완료, 저장 후 다시 열면 재생성 결과 동일

### M6. 래더 그림
- `layout.ts`(직렬·병렬 격자 배치), SVG 렌더링, 렁별 설명, 이상 번호 표, 오류·경고 렁 강조

## 위험과 대응

| 위험 | 대응 |
|---|---|
| GX Works2가 스텝 번호·형식 차이로 불러오기를 거부 | M1에서 샘플과 바이트 일치 테스트, M2에서 사용자 불러오기 관문을 두고 통과 전 진행 중단 |
| 코멘트가 8칸에서 줄이 바뀌지 않음 | M2 관문에서 확인, 다르면 채움 규칙만 `export.ts`에서 수정 |
| 한 스캔에 여러 단계가 넘어가는 연쇄 진행 | 전이 비트 블록과 단계 갱신 블록 분리(PRD 5-4), sim 테스트로 고정 |
| 병렬 합류·선택 분기 조합에서 단계가 둘 이상 잘못 활성 | 구조 검사(합류 없는 병렬 = 오류) + sim 테스트 |
| sim 해석기가 실제 PLC와 다르게 동작 | sim은 사용하는 명령만 구현, 최종 판정은 GX Works2 시뮬레이터(M8) |
| `claude -p` 플래그·출력 형식이 버전마다 다름 | 실행기 1개 파일에 격리, 구현 시 공식 문서 확인, 실패 시 API 방식으로 전환 가능 |
| LLM이 단계 표를 잘못 해석 | 스키마·주소 검사 + 사용자 단계 표 확인 단계를 항상 거침, 빠진 값은 질문으로 |
| 타이머 단위가 100ms가 아님 | 설정값으로 두고 설정 화면에서 변경 |
| P0 범위가 큼 | M2까지를 먼저 끝까지 뚫고(생성 → 내보내기 → GX Works2), 이후 단계별로 추가 |
